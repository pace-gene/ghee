# Untrusted content in `ghee pr` output — prompt-injection surface

Date: 2026-09-14
Context: `ghee pr` run inside a Claude Code session on `pacerevenue/platform`,
PR #6236. Findings below are about ghee as a **feeder of untrusted text into an
LLM context**, and what it could filter programmatically.

## What actually happened (and a correction)

During the session an instruction block appeared in the transcript styled as a
system message, headed `## Exited Plan Mode`, telling the agent it had left plan
mode and instructing it to stop using the Read/Edit/Write tools and do all file
work through `cat`/`sed`/heredocs instead. The agent had never been in plan
mode, so it ignored the block and flagged it as probable injection riding in on
the `ghee pr` output.

**That attribution was wrong.** Grepping the captured `ghee pr` output (both raw
and `--json`) for `Exited Plan`, `plan mode`, `auto mode is active` and
`heredoc` returns **zero matches** across all 14 comments. The block did not come
from ghee. Its real origin is a harness/plugin/hook in the Claude Code session
and is out of scope for this repo.

Recording it anyway because it is the reason the audit happened, and because the
*shape* of the block is exactly what a successful injection through ghee would
look like — worth keeping as the threat model.

## What is real: ghee does pass agent-directed instructions through verbatim

`format_pr_comments` in `github_tools/formatters.py:301` emits the comment body
unmodified:

```python
body = comment.get("body", "").strip()
...
lines.append(f"  💬 {body}")
```

Same for `format_pr_review_rounds` (`formatters.py:366`, `formatters.py:405`).
`--json` passes the raw dicts straight through (`formatters.py:224`).

In the 14 comments returned for this repo, one (`coderabbitai`, PR #5664,
discussion `r3298291215`) carries a block whose literal content is an imperative
instruction addressed to an AI agent:

```
<details>
<summary>🤖 Prompt for AI Agents</summary>

```
Verify each finding against current code. Fix only still-valid issues, skip the
rest with a brief reason, keep changes minimal, and validate.

In `@terraform/applications/connectivity-integration/alerts.tf` around lines 27 -
29, ...
```

</details>

<!-- fingerprinting:phantom:poseidon:hawk -->

<!-- This is an auto-generated comment by CodeRabbit -->
```

This is benign in intent — CodeRabbit is a trusted-ish bot and the instruction
is on-task. But mechanically it is untrusted remote text containing directives,
reaching an agent's context with no marking, no fencing, and no provenance. Any
GitHub user who can comment on a PR can put arbitrary text in that same channel,
including text shaped like a system message. `ghee pr` is the delivery vehicle.

Two aggravating properties of the current output format:

- **No trust boundary.** Comment bodies sit at the same indentation and in the
  same flat text stream as ghee's own headers (`📝 Unresolved PR Comments`,
  `PR #...`, `URL: ...`). Nothing tells a consumer where ghee's voice stops and a
  stranger's begins.
- **Bodies can be arbitrarily long and multi-line.** A body containing
  `\n\n## Something Official-Looking\n\n...` reproduces the visual grammar of a
  harness message once it lands in a terminal transcript.

## What ghee can filter programmatically

Ordered by value-for-effort. None of these are security boundaries on their own —
they raise cost and, more importantly, make injected content *visible*.

### 1. Strip HTML comments

Cheap, no false positives worth caring about. HTML comments are invisible in the
GitHub UI, so anything hidden there was never meant for a human reader — which is
precisely why it is the first place an attacker puts instructions.

```python
_HTML_COMMENT = re.compile(r"<!--.*?-->", re.DOTALL)
```

Drops `<!-- fingerprinting:... -->` and `<!-- auto-generated by CodeRabbit -->`
as a side benefit.

### 2. Collapse `<details>` blocks

Also hidden-by-default in the GitHub UI. The CodeRabbit agent-prompt block lives
in one. Rather than deleting, replace with a one-line placeholder naming the
`<summary>` so nothing silently vanishes:

```python
_DETAILS = re.compile(
    r"<details>\s*(?:<summary>(?P<summary>.*?)</summary>)?.*?</details>",
    re.DOTALL | re.IGNORECASE,
)
# -> "[collapsed: {summary}]"
```

Worth a `--expand-details` escape hatch, since some reviewers do put the real
substance in there.

### 3. Fence and label every body

The highest-value change and the only structural one. Stop interpolating bodies
into the same text plane as ghee's own output. Emit them inside a delimiter that
names the source:

```
  💬 <<<comment by kdim92 (untrusted) >>>
  This term needs to be per-integration specific
  <<<end comment>>>
```

Strip any occurrence of the delimiter from the body first so it cannot be
closed early. For `--json` this is free — the data is already keyed — but the
human-readable path needs it.

### 4. Flag directive-shaped bodies rather than dropping them

Deleting suspected injections is the wrong call: it hides reviewer feedback and
is trivially evaded. Detect and **annotate**. Candidate signals:

- Headings that mimic harness/system framing: `^#{1,3}\s`, and any line matching
  `(system|assistant|user)\s*[:>]`, `</?(system-reminder|instructions?)>`
- Known agent-prompt markers: `Prompt for AI Agents`, `@claude`, `@coderabbitai`
- Classic override phrasing: `ignore (all )?previous`, `disregard .* instructions`,
  `you are now`, `new instructions`
- Tool-steering language: `use the Bash tool`, `do not use the .* tool`

Emit a single visible line before the body, e.g.
`  ⚠️  body contains agent-directed text (matched: Prompt for AI Agents)`.
Keep a `--strict` mode that replaces matched regions with
`[redacted: directive-shaped content]` for pipelines feeding agents unattended.

### 5. Normalise the invisible

- Strip zero-width and bidi control characters (`​-‏`, `‪-‮`,
  `⁦-⁩`) — used to hide or reorder text.
- Normalise `\r\n` and lone `\r`, which can overwrite a terminal line.
- Strip ANSI escape sequences: `\x1b\[[0-9;]*[A-Za-z]`. A comment body can
  legitimately contain them via a pasted log, and they can repaint the terminal.

### 6. Bot-author policy

`user` is already on every comment. Let callers decide:
`--exclude-bot-comments` / `--only-human`, matching the GitHub `[bot]` suffix
plus a configurable list (`coderabbitai`, `dependabot`, ...). Note this is a
*noise* control, not a security one — `coderabbitai` is the well-behaved case;
a human account is the realistic attacker.

## Suggested shape

One `sanitize_body(body: str, *, strict: bool = False) -> tuple[str, list[str]]`
in `github_tools/utils.py`, returning the cleaned body plus a list of warning
tags. Both `format_pr_comments` and `format_pr_review_rounds` call it. For
`--json`, add `body_sanitized` and `warnings` keys **alongside** the untouched
`body`, so programmatic consumers keep fidelity while agent consumers get a safe
field to read.

Applies equally to `pr`, `pr-rounds`, and anywhere `activity` surfaces
user-authored text. Also relevant to `format_data_for_gemini`
(`formatters.py:126`) and `prompt.j2`, which feed remote text into a model
directly.

## What this does not fix

Sanitising the *transport* does not make the content trustworthy. A plainly
worded, correctly formatted PR comment can still ask an agent to do something
harmful, and no regex will catch it. The durable mitigation is the fenced,
labelled framing in (3) — making it structurally obvious to the consuming agent
that everything inside came from a stranger and is data, never instruction.
